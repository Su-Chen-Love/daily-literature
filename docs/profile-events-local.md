# 网页研究兴趣回传到本地

本地 SQLite 继续负责采集、Codex 判断和历史记录。网页保存的研究兴趣与筛选偏好通过追加事件回传；本补丁不启用云端主库、云采集或迁移分支。

## 消费与判断

- 同步入口识别 `profile_events_version=1`，按 `/api/sync/profile?after=N` 分页拉取。旧服务端不声明该能力时，继续原来的反馈同步。
- 每页事件、画像版本、筛选偏好、事件账本及 `cloud_profile_cursor` 在同一 SQLite 事务中提交。序号缺口、篡改重放和基础画像或偏好冲突会整体拒绝该页。
- 数据库提交后，以持久恢复标记原子更新画像文件；失败会在下一轮重试。未确认的本地文件编辑不会被覆盖。
- `collect-only` 开始前、`agent-export` 开始前均先执行只拉取同步。带采集的导出还会在采集与摘要补全完成后再拉取一次。同步忙碌或失败时停止本轮，不继续冻结旧画像队列。
- 队列冻结画像内容、画像哈希、筛选说明、偏好版本和阈值。导入按该队列的阈值解释结果。新兴趣只影响以后尚未判断的论文，不自动重评旧论文，不改变过去的推荐快照。

判断期间若画像正文发生变化，原有的导入画像校验仍会拒绝旧画像结果。重新导出尚未导入的论文并用新画像判断即可，不使用 `--rescreen`；仅阈值或筛选说明变更时，已冻结队列继续按原阈值导入。

如遇未确认的本地手工修改，先核对并另存需要保留的手稿，再将工作画像文件恢复为已确认基线或已消费的网页画像内容，然后重试同步。待恢复标记存在时，本地画像确认也会停止；不要直接清除游标或恢复标记来绕过冲突。

## 发布与确认

只拉取入口不上传、不切换快照、不确认事件。正常同步从同一读取事务导出完整快照，并仅确认该快照携带的 `profile_cursor`。较晚到达的网页兴趣仍保持待处理。

消费端配合现有 Site v10 的事件协议：事件版本领先快照游标时，网页继续显示最新编辑，旧快照不能遮蔽它。本补丁没有替换 Site 服务端；仓库历史版 `sites/` 不包含这套协议，不能直接部署它覆盖现有站点。更新界面时须保留现有兴趣读取、写入、事件分页及游标确认逻辑。

网页作者主动保存的兴趣是显式编辑。系统根据反馈提出的画像草稿仍需用户确认，不能因此自动激活。

## 验证

```sh
python -m unittest discover -s tests -v
```

`test_profile_sync.py` 覆盖事务、持久幂等、分页、冲突、文件恢复、旧服务端兼容及快照游标确认；`test_profile_pipeline.py` 覆盖采集与导出前的拉取、冻结偏好、历史评分保留及本地确认锁。测试使用临时合成数据库和模拟网络，不修改真实用户兴趣。

本补丁不修改每日任务的时间、来源、模型或同步周期，不新增凭据。首次正式同步自动应用追加迁移 `016_cloud_profile_events.sql`。
