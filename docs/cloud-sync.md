# Sites 部署与数据同步

> 本页下方描述迁移前的本地主库兼容流程。云端主库迁移以 [cloud-migration-runbook.md](cloud-migration-runbook.md) 为准：完整 SQLite/PDF 存入私有检查点，网站默认仅限所有者，Mac 仅备份。新代码不会自动完成部署或切换。

本地 SQLite 是采集、评分、来源配置、研究画像确认及 PDF 管理的主库。Sites 版以 D1 保存应用记录，复用本地六个页面的模板、CSS、JavaScript 和图标；界面只有运行地点与功能执行提示不同。云端直接保存兴趣、理由、收藏、阅读状态与清除操作，本地与云端反馈双向同步。

## 访问

当前目标访问策略为仅限当前所有者的 ChatGPT 账号。网站平台与应用均须校验所有者；没有配置可信所有者身份时，应用拒绝访问。旧版本曾允许匿名浏览和反馈；新版本仅在显式启用 SITE_ACCESS=public-legacy 时保留该兼容行为，正式迁移不得启用。研究兴趣与筛选偏好的保存始终需要所有者身份和同源校验。

来源配置、画像草稿与版本确认、手动文献或摘要导入及 PDF 管理仍在本地执行，随后把对应可展示记录同步到云端。云端可以查看这些内容；云端反馈保存与同步按钮可以直接使用。完整采集、摘要补全和语义评分依赖本地 Codex，每次“同步更新”只负责同步已有变化。

本项目站点：<https://personal-academic-radar.thuscuf.chatgpt.site>。

## 本地配置

配置与凭据放在私有状态目录，不进 Git。在现有 config.toml 加入：

```toml
[cloud_sync]
enabled = true
endpoint = "https://your-site.your-workspace.chatgpt.site"
credentials_file = "cloud-sync.json"
```

凭据文件权限设为 `0600`，包含 `sync_token` 与私有站点自动同步使用的 `sites_token`。同步凭据由所有者安全配置，并作为 Sites 的 `SYNC_TOKEN` 私密运行变量；不要把实际值写入命令参数、日志、仓库或文档。程序拒绝非 Sites HTTPS origin 和重定向，避免向其他地址转发凭据。

```bash
academic-radar sync --config /path/to/private/config.toml
academic-radar service install-sync --config /path/to/private/config.toml --interval 300
```

macOS 同步服务为 `com.personal-academic-radar.sync`，每 5 分钟检查一次，并在登录后启动。每日评分完整导入后也自动同步。本地反馈保存后会立即在后台安排同步，不阻塞保存；同步中再次编辑会安排下一轮读取，避免首次快照之后的修改遗漏。跨进程调用使用文件锁，繁忙时由现有调用或下一轮定时检查继续处理。

六个页面的侧边栏都有“同步更新”：本地按钮立即安排后台同步；云端按钮保存同步请求，本机在线且同步服务正常时由下一次 5 分钟检查处理。云端反馈立即写入 D1，无须等待电脑；电脑离线时可继续浏览与反馈，本地同步、采集和评分在恢复在线后继续。5 分钟是检查周期，网络故障或大批上传可能延迟完成。

同步分为三步：

1. 通过 GET 读取云端新增反馈事件、反馈游标和活动快照编号，将新事件与本地反馈在同一事务中合并。每篇反馈以 UTC 修改时间较新的整条记录为准；时间相同保留本地记录，重复事件不会重复写入历史。
2. 使用同一 SQLite 读取事务导出论文、推荐历史、画像、反馈和六页面上下文，计算逐记录 SHA-256 与整份快照编号。若编号与上次本地成功同步及云端活动版本一致，本轮只读取，不提交清单或上传论文数据；手动请求只需完成回执。
3. 有变化时只上传缺失或校验和不同的记录。分片全部校验通过后才原子切换云端活动版本，并确认已处理的请求与反馈游标。失败保留上一完整快照，后续可继续，云端保留上一完整版本作为恢复依据。

清除反馈会保存带修改时间的中性记录，页面不显示该记录；这个删除标记参与同步，旧事件不能让已清除反馈重新出现。收藏和阅读状态变化不改变语义偏好。兴趣、理由和画像变化用于校准后续尚未判断的论文；摘要更新也不会自动重评已判断论文。评分导出仍冻结反馈事件游标，并保留导出后新增偏好或证据变化的记录；这些记录不构成每日自动重评任务。只有用户明确要求时才手动重评，历史推荐快照不变。

同步状态显示“已完成”以云端确认的活动版本及请求回执为依据；云端存在尚未回传的反馈或手动请求时会显示等待本地在线处理。同步服务只传应用记录，发布接口使用私有同步凭据；新版本浏览与反馈接口默认要求已验证的所有者账号。

GitHub 和 Sites 源仓库只保存代码、测试、schema 和迁移。SQLite/WAL、PDF、配置、画像原文件、队列、结果、日志、备份与凭据不上传源仓库。向 D1 的应用记录同步是用户明确启用的独立通道。公开来源链接移除采集者联系信息和凭据查询参数，原始溯源仍留在本机。

## 部署与验证

站点源码在 `sites/`，逻辑 D1 绑定为 `DB`。数据库迁移由 Drizzle 生成并随部署包保存，不能把个人数据写进迁移。使用 Sites 插件的发布流程推送和打包精确源码，再部署保存版本。

```bash
cd sites
npm ci
npm run db:generate
npm run build
npm run validate
node scripts/test-worker.mjs
```

站点修改应同步到 GitHub 的对应源码，并重新发布。仅更新论文数据或反馈不需要重新部署源码。

`verify` 会检查每日更新、尚未判断论文、来源降级与云同步故障；旧判定标准或已判断论文的资料变化不要求每日重评。每日默认队列只处理从未判断的合格论文，默认 120 篇是单批上限，不是配额。私有 `cloud-sync-status.json`、`sync.stderr.log` 和 `sync.stdout.log` 提供恢复信息。摘要溯源缺口可使用 `abstracts verify-provenance` 在线核验；只有与本地原摘要全文一致的 DOI 元数据才补入真实来源，不改写摘要。其余缺口保留，并通过后续补全或人工证据核验。

共享界面的唯一来源是 `src/academic_radar/templates/` 和 `src/academic_radar/static/`。发布前运行 `python scripts/sync-site-ui.py` 更新 Sites 构建输入，再预编译模板并打包。`python scripts/sync-site-ui.py --check` 逐字节检查完整文件列表，拒绝缺失、多余或内容不同的文件；GitHub CI 在云端构建前执行此检查。迁移前兼容流程不传 PDF；云端主库模式通过私有 R2 检查点保存 PDF，并从已提交版本为所有者流式读取。语义评分仍由宿主执行，不引入独立模型 API。
